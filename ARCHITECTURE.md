# Architecture

## Agent shape — a workflow, not a swarm

TriageFlow is a **LangGraph state machine with tool-calling nodes**. The triage workflow is
*predictable*, so a fixed graph with agent nodes is the right tool — not autonomous
multi-agent delegation. (This follows directly from the "deterministic code where you can,
one graph where you must" principle; we add no reasoning boundary we can't justify.)

```
            ┌──────────────────── TriageAgent (LangGraph) — one fresh thread per run ───────────────────┐
 Encounter ─▶ validate ─▶ retrieve ─▶ score ─▶ deterioration ─▶ self_check ─▶ extract ─▶ ⏸ approval ─▶ finalize ─▶ Confirmed
            │   (own)     (borrowed)   (own)       (own)          (agent)     (own+LLM)   (human gate)    (own)
            │                                                   ▲ priority is on screen here, BEFORE any model call
            └── impossible value, no emergency sign ───────────────────────────────────────────────────▶ END (needs correction)
```

| Node | Does | Where |
|------|------|-------|
| `validate` | missing / impossible (error) / extreme-but-possible (warning, still scored) / stale / contradictory / wrong unit / under-12 | own MCP tool |
| `retrieve` | fetch the SATS protocol text | **borrowed** filesystem MCP (cached; local fallback) |
| `score` | **deterministic** TEWS + signs → sourced priority + the chart's "do now" actions | own MCP tool |
| `deterioration` | compare a re-check to its baseline → second-look flag | own MCP tool |
| `self_check` | verify every band sits in the right TEWS column and every sign under the right level of the protocol text; report local (non-SATS) rules | agent |
| `extract` | free text → **candidate** signs (keyword map + LLM, with a timeout), each to be accepted or dismissed by the nurse | own MCP tool + LLM |
| `approval` | `interrupt()` — pause for a named clinician | human gate |
| `finalize` | log the approval/override, return the confirmed priority | own MCP tool |

**Order matters.** Scoring runs *before* extraction, so the priority reaches the nurse within
a few seconds and a slow model can never delay it. An emergency sign ticked by the nurse
gives RED even if a vital was mistyped (the impossible value is dropped and reported).

### Why the LLM never scores
The priority is a pure function of vitals + published thresholds, implemented in
`core/scoring.py`. Given the same input it returns the same output every time (proven by
`tests/` and the determinism check in `evals/run.py`). The open-weights model only
(a) proposes candidate signs from free text, which do nothing until the nurse accepts them,
and (b) *if switched on* (`TRIAGEFLOW_HANDOVER_NOTE=1`, off by default) writes a handover
note outside the gate path. That note is not given the "do now" actions, and it is discarded
unless it states the proposed priority, names no other colour, uses no diagnostic language
and claims nothing was done — in testing the model once reported a prompted glucose test as
"done", which is why the default handover is the summary generated by code. Every LLM step has a timeout and a deterministic fallback, so a slow or
absent model degrades gracefully rather than breaking the run.

### What is derived, what is suggested, what is local

| Kind | Example | Applied how |
|------|---------|-------------|
| **Derived from a structured reading** (SATS) | AVPU not "alert" → *reduced level of consciousness* (very urgent); glucose ≤ 3.0 → hypoglycaemia (emergency); pain score → pain sign | automatically, with its citation |
| **Suggested** | "chest pain" in the complaint; glucose > 11 → the diabetic signs | only after the nurse marks it *present* |
| **Local convention, not SATS** | adult SpO₂ < 92% → at least ORANGE; 0–10 pain cut-offs; deterioration watch | applied, but **labelled** as local in the evidence, the UI and the self-check |

### Run isolation and the gate
Each assessment runs on its own checkpointer thread (`run_id`), so state from an earlier run
of the same encounter can never be shown or approved. `approve(run_id, decision)` refuses —
with a message for the clinician — unless the run is paused at the gate and: the approver is
named; there is a priority (or a reasoned override); every suggested sign has been reviewed;
the nurse has attested to checking the sign list when the model did not read the complaint;
and the self-check passed. The same rules are repeated inside the
`request_clinician_approval` tool, so they hold for any MCP client.

## MCP servers — built vs borrowed

**Built — `triageflow` (`src/triageflow/mcp/server.py`).** The agent's hands. Six tools:
three *act* (`score_triage`, `check_deterioration`, `request_clinician_approval`), plus
`validate_triage_input`, `suggest_discriminators` and the optional `fetch_fhir_vitals`. Each
call is written to an append-only audit log (JSONL + SQLite) with inputs, outputs, timestamps
and errors. The tool boundaries are reusable by any MCP client, not just our UI.

**Borrowed — `@modelcontextprotocol/server-filesystem`** (official reference, run via
`npx`), read-only over `protocols/`. It backs `retrieve` so the self-check can compare the
evidence with the protocol text. *Why borrow over build:* sandboxed, path-traversal-safe file
access is a solved, security-sensitive problem; reusing the audited reference is safer and
faster than re-implementing it. *Why this over alternatives we evaluated:* the official
SQLite MCP is archived/unmaintained, and third-party FHIR MCPs have unverified maintenance
plus Docker friction that would threaten the one-command rule.

Our own server connects first and is all the app waits for. The borrowed one attaches in the
background with a timeout; if Node is missing or the network is down, the protocol text is
read from the local file and the trace says so.

*(Interoperability extension, documented not required: a FHIR MCP + HAPI server is the path
to reading/writing encounters against a real EMR — our data is already FHIR R4-shaped.)*

## Control, cost & residency

- **Human-in-the-loop** is a real graph `interrupt()`, not a prompt instruction: the graph
  cannot reach `finalize` without a resume carrying a named clinician's decision.
- **Cost per run** is bounded and known: the clinical path is deterministic (0 tokens); the
  LLM adds one short extraction (capped at `max_tokens=120`) and, only if opted in, one
  handover note. `TRIAGEFLOW_NO_LLM=1` makes it zero-token end to end.
- **Data residency:** inference is local; synthetic data only; the data region is recorded in
  config and shown in the UI. Patient data never leaves the machine.
- **Pluggable runtime:** the LLM is reached through an **OpenAI-compatible** client, so the
  backend (`TRIAGEFLOW_LLM_BACKEND`) is swappable with no code change — **llama.cpp**
  `llama-server` (primary) or **Ollama**. Each backend owns its server lifecycle + model
  download and exposes a catalog so a nurse can switch to a lighter model on a low-powered box.

### Model runtime on any desk PC
`agent/llamacpp_backend.py` makes llama.cpp work from one command on Windows, macOS and Linux:

1. **Find** `llama-server` on PATH, else one already unpacked under `~/.triageflow/bin`.
2. **Provision** if absent: resolve the build the latest *stable* llama.cpp release points to
   (falling back to recent builds, then a pinned tag if the GitHub API is unreachable), pick
   the CPU asset for this OS/architecture, download it with resume + retry, unpack it with
   path-traversal checks, and **run it** (`--version`) — the only real proof it works here.
3. **Serve**: start it on the configured port (or a free one if that is taken), log to
   `~/.triageflow/logs/`, health-check it, retry once with minimal flags if an older build
   rejects an optional one, and stop the child process when the app exits.
4. **Models**: reuse a GGUF Ollama already has; otherwise download with a disk-space check and
   a GGUF integrity check.
5. **Self-heal**: if the runtime we unpacked stops running (files removed, quarantined), it is
   fetched again before the next start. A server found on the port is adopted only if it
   really answers the model API.
6. **Clean exit**: Ctrl+C, a closed terminal window (SIGHUP) or SIGTERM all stop the model
   server — even mid-load. If the app is killed outright, the next start finds the server it
   left behind (by pid file, on whatever port it used), reuses it, and stops it on exit; a
   stale pid that now belongs to another program is never touched.

`auto` selects llama.cpp for exactly this reason: it needs nothing else to be running. The
Ollama backend remains available; when Ollama's server is down it reads Ollama's manifests
from disk, so downloaded models are never reported as missing. CI runs
`evals/runtime_smoke.py` on Linux, Windows and macOS — real binary, real server, real tokens.

The web server never waits for any of this — it listens within a couple of seconds and the
model switches on when ready.

## Layout

```
src/triageflow/
  core/        sats_rules, scoring, validation, explain, lexicon, models, audit, config  ← deterministic heart
  data/        fhir (LOINC), synthetic scenarios                        ← EMR-shaped synthetic
  mcp/         server.py                                                 ← our MCP server
  agent/       graph.py (LangGraph), mcp_client.py, llm_backend + llamacpp/ollama backends, downloads  ← orchestration
  web/         app.py (FastAPI) + templates/ + static/                   ← nurse workspace
protocols/     sats_adult.md                                            ← protocol text (borrowed MCP serves this)
tests/         SATS table, validation, agent flow + gate, synthetic set, runtime provisioning, web API
evals/         cases.py + run.py (scoring, flow, synthetic set, sign-finding recall)
```
